Scene Orchestrator Engine Integration Plan

Goal

Evaluate and integrate Icehellionx's "Scene Orchestrator Engine" into the World Forge JanitorAI export pipeline.

Evaluation

Should we implement it? Yes, but not by copy-pasting the raw script. Why?

  1. Token & Performance Bloat: The raw script includes a 350-line custom keyword-matching engine. Our Janitor_Script_World_Template.js already has a highly optimized, feature-rich keyword engine (dynamicLore) created by lys_5. Running two separate keyword parsers per message is inefficient and consumes precious JanitorAI context tokens.
  2. Context Relevance: Icehellionx's packs contain modern/urban keywords (subway, laptop, espresso). Hardcoding these into every template would pollute fantasy or sci-fi bots. The Solution: We will absorb the logic and rules of the Scene Orchestrator directly into our existing dynamicLore array format. We will make the universally useful rules (Meta, Time Jumps) native to the templates, and make the contextual rules (Weather, Location, Props) dynamically generated by the Architect based on the world.

Proposed Changes

1. Template Updates (templates/Janitor_Script_World_Template.js and others)

We will natively integrate the universally applicable "Meta" and "Time Jump" rules into the base dynamicLore array of our templates. These rules handle OOC chat, flashbacks, and time skips, which apply to every roleplay setting. Example addition to dynamicLore:

{
	keywords: ['ooc', 'out of character', 'meta chat', 'author note'],
	priority: 5,
	scenario: ' [SCENE ORCHESTRATOR]: Record that the user is speaking out of character; do not progress the in-world scene.',
	personality: ' [SCENE ORCHESTRATOR]: Mark tone as meta-communication handling; respond outside of narrative voice.'
},
{
	keywords: ['time skip', 'timeskip', 'fast forward', 'next day'],
	priority: 5,
	scenario: ' [SCENE ORCHESTRATOR]: Record that a time skip or scene jump is requested.'
}
2. Architect Agent (agent_roles/02_The_Architect.md)

We will add a new phase/instruction for Scene Orchestrator Packs . If the world is complex enough to require tracking locations, weather, or props, the Architect will generate a Drafts/Tier1_Scene_Orchestrator.md file containing a JSON array of dynamicLore objects formatted specifically for that world (e.g., sci-fi props, fantasy locations).

3. Compiler Agent (agent_roles/04_The_Compiler.md)

The Compiler will be instructed to extract the JSON from Tier1_Scene_Orchestrator.md and save it as Export/[WorldName]_Scene_Orchestrator.json.

4. Builder Script (tools/build_janitor.py)

We will modify the Python builder to detect [WorldName]_Scene_Orchestrator.json. If found, the builder will inject these additional objects into the dynamicLore array of the World_Template.js (just like we did for Random Events).

5. Workflow Documentation (workflows/world-forge.md)

Update the pipeline steps to include the new Tier1_Scene_Orchestrator.md and its compiled JSON counterpart.
